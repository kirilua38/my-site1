# Сайт компании для водителей — веб-проект, НЕ Roblox

Это сайт (HTML/CSS/JS), а не игра на Luau. Из глобального `~/.claude/CLAUDE.md` здесь действуют только вступление (я учусь — поясняй термины) и «Как работаем».
Не действуют: «Формат плана», «Рабочий цикл», «Архитектура Roblox-проектов», «Клиент и сервер», «Studio и синхронизация», `~/.claude/rules/luau.md`, `check.sh`, `/playtest`, агенты `place-inspector` и `studio-tester`, Studio MCP. Вместо них — правила ниже.

## Проект
- Этап 1 — копия: максимально точно повторяем https://eurodrivers.com.ua/ (наш же сайт на Tilda, права на тексты и фото есть).
- Страницы этапа 1: главная, «Код 95» (`/kod95ukr`), «Чип-карта» (`/chipcard`), «Контакты» (`/contacts`), модальное окно «Зворотній дзвінок» (`#popup:callback`).
- Этап 2 — ребрендинг: новое имя и новый стиль. Пиши код так, чтобы смена стиля не требовала переписывать разметку.
- Язык сайта — украинский, со мной общаемся по-русски.
- Сайт живёт на хостинге (какой — решим в плане), заявки уходят в Telegram-бота. Адаптивность под телефон обязательна.

## Стек и код
- Чистые HTML + CSS + JavaScript, без фреймворков, сборщиков и jQuery. Сменить стек — только через план и запись в `docs/decisions/`.
- Ничего не подключай с серверов Tilda (`tildacdn`): из оригинала берём тексты, картинки и внешний вид, но не его код.
- Цвета, шрифты, радиусы, тени, ширина контейнера — только CSS-переменные из `css/variables.css`. В остальных CSS-файлах голых цветов нет.
- Mobile-first: базовые стили пиши для телефона, `@media (min-width: …)` — для экранов шире. Точки перелома (breakpoints) одинаковые на всех страницах.
- Шапка и подвал копируются на каждую страницу: правишь их на одной — правь на всех и перечисли файлы.
- Телефоны, почту, адрес и название компании пиши везде в одном формате, чтобы при ребрендинге найти их поиском.
- Картинки — в `img/`, сжатые, с `width`, `height` и `alt`; ниже первого экрана — `loading="lazy"`.
- У каждой страницы свои `<title>` и `<meta name="description">` и ровно один `<h1>`.
- Скрипты подключай с `defer`. Трекеры (Facebook Pixel, аналитику) не переноси без моей просьбы.
- Модальное окно закрывается крестиком, по Esc и кликом по фону; у каждого поля формы есть подпись.

## Заявки и секреты
- Токен бота и `chat_id` хранятся только на сервере, в файле из `.gitignore`. В HTML, JS и git их нет никогда.
- Браузер шлёт форму на наш обработчик, обработчик — в Telegram. Напрямую из браузера в Telegram не ходим.
- Обработчик проверяет каждую заявку (как ремоут в Roblox: клиент просит, сервер решает):
  1. формат: телефон — только цифры и `+`, длина в рамках; имя — по длине; лишние поля отбрасываются;
  2. ловушка для ботов (honeypot): скрытое поле, которое человек не видит, должно быть пустым;
  3. частота: не больше N заявок с одного IP за период.
- Невалидную заявку отклоняй без подробностей в ответе. Текст из формы экранируй перед вставкой в сообщение Telegram.

## Размер задачи
Перед работой назови размер одной строкой с причиной. Сомневаешься — фича.
- **Мелкая** — всё сразу: правка в 1–2 существующих файлах; без новых страниц, секций и файлов; не трогает форму, обработчик, секреты, шапку и подвал. Примеры: текст, картинка, отступ, цвет, баг внутри одного блока. Правка значения в `variables.css` — мелкая, но проверяй все страницы.
- **Фича** — всё остальное.

**Мелкая:** одной строкой «что и где меняю» → моё «да» → правка → превью этой страницы на 375 и 1280 → смотрю я.

**Фича:**
1. Прочитай `docs/` (решения, планы). Противоречие с решением — скажи явно.
2. План по формату ниже → моё «да». План из 2+ шагов сохраняй через `/doc plan`.
3. Шаг — один элемент: одна секция страницы, один компонент (шапка, подвал, модалка) или обработчик. Целую страницу за шаг не пиши.
4. После шага — «Проверка», затем разбор 3–5 строк: **приём** (как называется), **почему так** и что отвергнуто, **на что смотреть при ревью**.
5. Следующий шаг — только после того, как я посмотрел и сказал «дальше».
6. Перед коммитом: форма, обработчик, секреты → `/security-review`; новая страница и крупные правки → `/code-review`.

## Формат плана
Коротко, по пунктам, без кода. Пункт, который к задаче не относится, пропускай.
1. **Цель.** Что посетитель увидит или сможет сделать. Неясно — сначала вопросы.
2. **Оригинал.** Какой блок eurodrivers.com.ua повторяем и что из него берём: тексты, картинки, поведение (слайдер, аккордеон, анимация).
3. **Файлы.** Новые и изменяемые; какие страницы задеты.
4. **Адаптивность.** Как блок перестраивается на телефоне.
5. **Формы.** Поля, куда уходят, как проходят три проверки.
6. **Шаги.** Нумерованные, по одному элементу, каждый проверяется отдельно.
7. **Риски.** Что может сломаться на других страницах; что нельзя проверить локально (например, отправку в Telegram).

## Проверка
- Превью — локальный сервер из `.claude/launch.json` во встроенном браузере (настроим в первом шаге каркаса).
- Ширины 375, 768 и 1280: нет горизонтальной прокрутки, ничего не наезжает, консоль без ошибок.
- Сравнивай с тем же блоком оригинала на тех же ширинах.
- Пока нет `scripts/check.sh`, норма — чистая консоль. Появится — запускай после каждой правки.
